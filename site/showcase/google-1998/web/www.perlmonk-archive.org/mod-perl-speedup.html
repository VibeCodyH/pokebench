Migrating Slow CGI Scripts to Apache::Registry
PerlMonk 5.004 Archive | Randall Mercer & Contributors | 09-Sep-1998

Every plain CGI request spawns a brand-new Perl interpreter (~85ms fork/compile penalty). Compiling mod_perl 1.15 into Apache 1.3.1 runs Apache::Registry scripts in-process, jumping throughput from 14 req/s to 185 req/s on a Pentium II 300.

# Watch out for persistent globals under Apache::Registry!
use strict;
my $hits = 0;  # BUG if inside outer closure! Reset per request:
sub handler { my $r = shift; my $req_hits = 1; ... }

Production Note: Enable PerlWarn On in httpd.conf to catch closure variable leaks early.

Perl 5.004 Environment & Testing Note: Verify scripts from the shell with perl -wcT script.cgi before copying them into /usr/local/apache/cgi-bin. Under Apache mod_perl or standard CGI, inspect /var/log/httpd/error_log with tail -f to catch premature end-of-script-headers and uninitialized $_ warnings.
