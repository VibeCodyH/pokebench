Rebuilding VSAM KSDS Keys Containing YYDDD Julian Dates

Sequential transaction lookups break catastrophically when a VSAM Key-Sequenced Data Set (KSDS) embeds YYDDD at byte offset 0 of its primary key. Reading STARTBR with 00001 wraps to the front of the B-tree ahead of 1991-1999 records!

  • Option A (Best): Re-define cluster via IDCAMS DEFINE CLUSTER with 4-byte YYYYDDD key and reload.
  • Option B (Zero Schema Change): Store inverted CYYDDD where C=1 for 2000+ (matches CICS!).
