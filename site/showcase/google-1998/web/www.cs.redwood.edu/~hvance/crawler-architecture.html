Distributed Web Crawling in C++ and Solaris Threads
Prof. Harold Vance | Systems Note -- 02-Sep-1998

Fetching millions of pages over university T3 lines requires asynchronous non-blocking sockets paired with a Solaris libthread worker pool. Each worker holds up to 64 concurrent HTTP/1.0 GET descriptors, caches DNS lookups locally to avoid saturating our BIND 8 resolver, and enforces a 15-second per-host politeness gap alongside strict /robots.txt exclusion rules.

struct CrawlFrontierEntry {
    uint64_t url_md5_hi;   /* 64-bit MD5 deduplication key */
    uint32_t host_hash;    /* per-server politeness bucket */
    char     url[512];
};

Our URL frontier strips session IDs and infinite CGI calendar loops to avoid crawler traps. Thanks to Megan O'Malley's Grad Page for debugging the NFS locking contention on the barrel output directory. Note for Linux cluster nodes: check the compiler warning in [borealis-dev] Re: egcs 1.1b. Weekend crawler stress test logs even pulled pages like ChronoBlade 64 Sanctuary without crashing our parser.
